# fund_data.py Split — 0.3.0 RFC

**Status:** draft, awaiting review.
**Author:** Mavis (session `mvs_8c580fb7d3fa42ca89b0f70b9bfd4efd`).
**Date:** 2026-06-02.
**Target release:** 0.3.0.

## Goal

Split `fund-data/scripts/fund_data.py` (3605 lines) into a
package of focused modules so the next round of capability
additions (KNOWN_GAPS #1 / #5 / #6 / #7) is not blocked by a
single-file monolith. Keep the public API byte-identical so
every existing CLI / MCP / test / agent contract survives
unchanged.

## Why now

`fund_data.py` mixes nine concerns in one file:

| Concern | Lines | Why it wants to leave |
|---|---|---|
| Path resolver + constants | 35 | Trivially testable; nothing else should depend on the resolver |
| Schema migrations | 175 | Only `ensure_schema` needs them; test fixtures want a clean stub |
| Normalizers (float / date / text) | 196 | Reused by parsers + store + sync; noisy in test output |
| HTML / JSON parsers | 163 | Pure functions; ideal for property-based testing |
| HTTP client + rate limiter | 125 | Used by all 4 providers; isolation helps mock the network |
| Provider classes (4) | 1235 | The single biggest cost-of-understanding line item; each is independent |
| Provider chain builder | 66 | Glue only; tested indirectly via the 4 providers |
| `FundDataStore` | 733 | Big class, but only knows about schema + SQL; the most-split-candidate |
| `fetch_*` convenience functions | 328 | Thin wrappers over provider + store; tested by integration not unit |
| `sync_fund` / `batch_sync` / `coverage_*` | 472 | Orchestration; should be the last thing moved (depends on all above) |

Symptoms of the monolith:

- **Test cost**: 7 of the 11 test files under `tests/` mock
  `fund_data` to avoid pulling in 3605 lines of unrelated
  logic. The mock surface is fragile (renaming a helper
  breaks 5+ test files).
- **Code review cost**: a 50-line PR that touches one provider
  still requires the reviewer to load all 3605 lines into
  context to spot side effects.
- **CI cost**: a typo in any of the 3605 lines forces the
  whole test run to import everything; cold-test time on
  Python 3.13 is ~4 s where it could be ~1 s for a unit that
  only needs `normalizers.py`.
- **Onboarding cost**: a new contributor has to read the
  whole file to find the right function. Every
  `fund-data/scripts/<x>.py` script has a top-of-file
  comment pointing back at `fund_data.py` and listing which
  functions it uses; the lists are stale.

## Shape

Replace the 3605-line file with a `fund_data` package and a
70-line facade re-export so every existing import keeps
working.

```
fund-data/scripts/fund_data/                  # package (replaces fund_data.py)
├── __init__.py                              # ~80  — facade re-export of public names
├── paths.py                                 # ~50  — default_db_path, utc_now, schema constants
├── schema/
│   ├── __init__.py                          # ~30  — ensure_schema, REQUIRED_TABLES, SCHEMA_VERSION
│   └── migrations.py                        # ~175 — _migration_001 .. _migration_005
├── normalizers.py                           # ~250 — float/date/text helpers + normalize_fund_code
├── parsers.py                               # ~250 — _TableParser + 5 parse_* + JS fragment helpers
├── http.py                                  # ~125 — FundDataClient, _RateLimiter
├── providers/
│   ├── __init__.py                          # ~100 — PROVIDER_* constants + build_providers + build_providers_full
│   ├── base.py                              # ~50  — ProviderError, ProviderResult, run_provider_chain
│   ├── eastmoney.py                         # ~50  — EastmoneyProvider
│   ├── akshare.py                           # ~750 — AkshareProvider (largest single file)
│   ├── investoday.py                        # ~250 — InvestodayProvider
│   └── tushare.py                           # ~200 — TushareProvider + _tushare_period
├── store.py                                 # ~750 — FundDataStore
├── fetch.py                                 # ~330 — 12 fetch_* convenience functions
└── sync.py                                  # ~500 — sync_fund, batch_sync_funds, coverage_*

fund-data/scripts/fund_data.py                # ~70  — facade: re-exports + deprecation warnings
```

### Dependency graph (must be acyclic)

```
paths  →  (stdlib only)
schema  →  paths
normalizers  →  paths
parsers  →  normalizers
http  →  paths
providers.base  →  http
providers.{eastmoney,akshare,investoday,tushare}  →  base, normalizers
providers.__init__  →  all 4 providers
store  →  schema, normalizers
fetch  →  providers, store
sync  →  fetch, store
fund_data.py  →  everything (re-export only)
```

Acyclic, single-direction. Any `from .foo import Bar` in a
module earlier in the list is a bug — file an issue and
re-order, do not paper over with `TYPE_CHECKING` guards.

### What stays put

- `from scripts import fund_data` — every test, CLI, MCP,
  and docstring keeps working.
- `fund_data.AkshareProvider`, `fund_data.InvestodayProvider`,
  etc. — the public class names are re-exported from
  `fund_data/__init__.py` so the four `from scripts import
  fund_data; fund_data.AkshareProvider(...)` sites work
  without edits.
- `fund_data.default_db_path`, `fund_data.coverage_report`,
  `fund_data.sync_fund`, `fund_data.batch_sync_funds` —
  all convenience entry points re-exported.
- `pyproject.toml` package config — does not need a change
  because Python sees `fund_data.py` and `fund_data/` as the
  same module either way.

### What breaks (intentionally, but we want to know about it)

- **Private names with a leading underscore** are not
  re-exported by the facade. Grep the tree for
  `from scripts.fund_data import _` — there should be zero
  hits in `tests/` and the 11 script entry points. We
  checked; zero hits as of 2026-06-02.
- **The `fund_data` package directory on disk collides with
  the `fund_data` module path** for any code that does
  `import fund_data; fund_data.foo()`. There is exactly one
  such site: the `scripts/fund_data.py` shim is itself the
  problem we are solving. Once the package replaces the
  file, the only callers are `from fund_data import ...`
  (which goes through the new package) and the local
  `import fund_cloud, fund_data` shim inside `fund_mcp.py`
  (covered by the facade).

## Scope

In scope:

- 5 sequential PRs (one per dependency layer, ordered).
- A facade re-export module + the `fund_data.py` shim.
- Unit test split: the existing `test_fund_data.py` (which
  currently tests 8 unrelated subsystems in one file) gets
  re-homed next to the module each test now covers:
  `test_paths.py`, `test_normalizers.py`, `test_parsers.py`,
  `test_http.py`, `test_providers_*.py`, `test_store.py`,
  `test_fetch.py`, `test_sync.py`. Tests are moved, not
  rewritten — assertion count must be preserved.
- CI: `pyproject.toml`, `requirements.txt`, `lint.yml`,
  `test.yml`, `nightly.yml` do not need changes.

Out of scope (separate RFCs):

- The actual `FundDataStore` refactor (e.g. moving methods
  out into `store/funds.py`, `store/holdings.py`). It will
  become easier after the split but the 0.3.0 RFC does not
  promise it.
- Replacing the `FundDataStore` class with a query builder.
- Async / `asyncio` migration of `FundDataClient`.
- Move from SQLite to Postgres (mentioned in some
  back-of-envelope designs; not on the 0.3.0 roadmap).

## Cross-cutting effects

### KNOWN_GAPS items this unblocks

- **#1 `fund_managers` bulk sync** — currently a 9 h AkShare
  serial run. After the split, `providers/akshare.py` can
  be imported + tested in isolation, and a one-shot
  `scripts/akshare_fund_managers_bulk.py` runner can be
  added without disturbing any other code. Estimated PR
  cost drops from "edit the monolith" to "add a file under
  `scripts/`".
- **#5 `fund_managers` fund-centric link** — the
  `fund_manager_links` view becomes `store.fund_manager_links`
  (one method on `FundDataStore`) rather than "edit
  `fund_data.py` to add a new SQL string somewhere".
- **#6 `refresh_fund_type` nightly** — already has a
  script (`scripts/refresh_fund_type.py`); the split just
  makes its `from scripts import fund_data` import 5×
  faster on the cold path and removes the temptation to
  reach into private helpers.
- **#7 `akshare_capability_backfill` schema drift** —
  `_merge_separate_db` lives in
  `scripts/akshare_capability_backfill.py`, but the
  underlying `FundDataStore` methods it calls are now in
  one well-scoped place (`store.py`) where the explicit
  column lists can land.

### Agent / user-facing surface

Zero. The `fund_mcp.py` server, the `fund_cli.py` subcommands,
the `doctor.py` checks, the `coverage_report.py` schema, the
`install_skill.py` Python API — all continue to call
`fund_data.foo()` and get exactly the same object back. The
only externally observable change is import time on cold
start, which drops by an order of magnitude for the
components that did not need the full file (most of the
`scripts/*.py` entry points).

## Implementation plan

5 PRs, each independently shippable. Each PR adds new
files under `fund_data/` AND keeps `fund_data.py` as a
facade so the previous PR's tests keep passing. The final
PR is the only one that does not modify `fund_data.py`.

### PR 1 — paths + schema (lowest risk)

- Add `fund_data/__init__.py` (empty package marker only;
  the facade import work starts in PR 5).
- Add `fund_data/paths.py` with `default_db_path`,
  `utc_now`, `DEFAULT_DB_PATH`, and the other module-level
  constants used by 5+ other modules.
- Add `fund_data/schema/__init__.py` and
  `fund_data/schema/migrations.py`. Move `ensure_schema`
  and the 5 `_migration_00N_*` functions.
- Update `fund_data.py` to `from .fund_data.paths import *
  ; from .fund_data.schema import *`.
- Move `test_default_db_path` from `test_fund_data.py` to
  `test_paths.py` (new file).
- **Validation**: `./run_tests.sh` 262/262 still pass; the
  `fund_data.py` shim is ~50 lines of re-exports.
- **Diff size**: ~300 lines (175 migration move + 50 paths
  + 50 init + 50 shim).

### PR 2 — normalizers

- Add `fund_data/normalizers.py`. Move all `_to_float`,
  `_json_dumps`, `_records`, `_first_*`, `_rate_to_decimal`,
  `_ratio_value`, `_normalize_date_text`,
  `_normalize_report_period`, `_fee_indicator_alias`,
  `_profile_dict`, `_clean_text`, `_is_missing`, plus the
  public `normalize_fund_code` and `normalize_fund_codes`.
- Add `fund_data.py` re-export shim.
- **Validation**: `./run_tests.sh` still 262/262.
- **Diff size**: ~350 lines.

### PR 3 — parsers

- Add `fund_data/parsers.py`. Move `_TableParser`,
  `parse_search_results`, `parse_fund_code_list`,
  `parse_fund_codes`, `parse_nav_history`, `parse_snapshot`,
  `_extract_js_string`, `_extract_js_array`,
  `_decode_js_fragment`, `_extract_payload_records`.
- **Validation**: 262/262.
- **Diff size**: ~350 lines.

### PR 4 — HTTP client + 4 providers

- Add `fund_data/http.py` (`FundDataClient`, `_RateLimiter`).
- Add `fund_data/providers/{__init__,base,eastmoney,akshare,investoday,tushare}.py`.
- Move all 4 provider classes verbatim. They share the
  `ProviderError` base via `providers/base.py` so the import
  graph is clean.
- **Validation**: 262/262; integration smoke
  `fund_cli search 易方达` from a clean checkout returns
  results.
- **Diff size**: ~1700 lines (the biggest single PR).

### PR 5 — store + fetch + sync (no facade yet)

- Add `fund_data/store.py` (`FundDataStore`).
- Add `fund_data/fetch.py` (the 12 `fetch_*` convenience
  functions).
- Add `fund_data/sync.py` (`sync_fund`, `batch_sync_funds`,
  `coverage_rows`, `coverage_report`).
- **Validation**: 262/262; `fund_cli doctor` still works;
  `fund_mcp` still answers `tools/list`.

### PR 6 — finalize the facade

- Replace `fund_data.py`'s body with a single deprecation
  banner + 4 lines of re-exports pointing at the package.
- Make `fund_data.py` an empty marker (`pass` after the
  banner) so `from scripts import fund_data` keeps working
  as a no-op double-import. Actually, prefer the alternative:
  delete `fund_data.py` entirely and have callers do
  `from scripts import fund_data as fd` (the package
  shadows the missing file with no Python error). The PR
  includes the script-side search-and-replace of
  `from scripts import fund_data` to keep the alias
  working.
- **Validation**: 262/262; full smoke
  `./run_tests.sh && fund_cli doctor --skip-network
  && fund_mcp < /dev/null`.

### PR ordering rationale

Each PR ends in a working state. We can stop after any PR
and the codebase is shippable. The dependency graph is
linear, so we cannot usefully parallelize the PRs — each
later PR depends on the import surface the earlier PR
introduced. Within a PR, the file moves are mostly
copy-paste (no logic change), so review is fast.

## Testing strategy

Three layers, all already in place:

1. **Unit tests** (`./run_tests.sh` — 262 cases today).
   Moved alongside the module they cover, never rewritten.
   This is the contract that PR review runs against.
2. **Provider integration smoke** (new, after PR 4):
   `fund_cli search 易方达 --limit 1` from a clean
   checkout must return 1 result within 10 s. Added as a
   separate test file `tests/test_provider_smoke.py` that
   is **marked skip-on-no-network** so it does not break
   the offline `run_tests.sh` flow. CI runs it in `test.yml`
   on a non-required job.
3. **`fund_mcp` end-to-end** (new, after PR 5):
   `fund_mcp < /dev/null` exits 0 with the protocol
   `initialize` handshake. Already covered by
   `test_fund_mcp.py` for the protocol flow, but we want
   a "real" smoke that spawns the binary, not the
   function. Optional follow-up.

The 4 new integration tests above are added in the same PR
that introduces the module they cover, not in a single
"tests" PR at the end — otherwise PR 1–4 would be reviewable
only by a human running them by hand.

## Risks and mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Circular import (e.g. `fetch.py` reaches back into `store.py` for a constant that `store.py` got from `schema.py`) | Medium | PR fails to load | Strict linear order + a `tests/test_import_graph.py` that walks `importlib` and asserts no cycle |
| Facade misses a public name → a downstream script crashes with `ImportError` | Medium | PR broken on day 1 | The `pyproject.toml` already has a `[tool.setuptools]` config that auto-discovers; use it. Add a `tests/test_facade_completeness.py` that imports every name listed in the original `fund_data.py` top-of-file docstring and asserts the facade still has it |
| Test runtime regression (each PR adds an import) | Low | Slower CI | Each PR's CI run is benchmarked; the 5-PR series ends < 2 s of extra total runtime |
| Cython / native extension pinned to a specific module path | None (no C extensions in fund_data.py) | n/a | n/a |
| `pyproject.toml` `[tool.setuptools.packages.find]` accidentally picks up the new package twice (once as `fund_data` directory, once as `fund_data.py` shim) | Medium | Wheel install fails | PR 6 deletes `fund_data.py`; earlier PRs add a `# legacy-shim-do-not-add-to-wheel` comment so the shim is documented as a no-go |
| Other monorepo packages (e.g. `fund_cloud.py` which does `from . import fund_data`) silently break | Low | Tests pass but `fund_mcp` runtime ImportError | The same `test_facade_completeness.py` boots `fund_mcp`'s `handle_message` and asserts the import surface |

## What we are NOT doing in this RFC

- **Async / `asyncio` rewrite** of `FundDataClient`. The
  sync client works, the test suite is synchronous, and a
  separate RFC can tackle that without blocking on the
  split.
- **Switching from SQLite to anything else**. The schema
  migrations live in `fund_data/schema/migrations.py` and
  are SQLite-flavoured; that is fine for 0.3.0.
- **Removing the `_underscore_prefixed` private helpers**.
  They are private, but the test files reach into them in
  a couple of places; we want zero behavior change in this
  RFC, so we just move them.
- **Splitting `FundDataStore` further** (e.g. one method
  per table). That is a real refactor; it deserves its own
  RFC after the package split ships.
- **Touching the public CLI / MCP surface** (adding /
  removing flags, changing `tools/list` output, etc.). The
  `MainOutputSchemaTests` and `test_fund_mcp.py` are
  load-bearing and we do not want to touch them in the
  same PR as the split.

## Open questions for review

1. **Should the shim `fund_data.py` stay (deprecation
   banner) or be deleted in PR 6?** Deleting is cleaner
   but requires touching every `from scripts import
   fund_data` site to add `as fd` or similar. Keeping the
   shim is one line of import noise. **My recommendation**:
   keep the shim with a `DeprecationWarning` so an
   operator can grep the codebase for offenders and plan
   the 0.4.0 cleanup at their own pace.
2. **Does the `__init__.py` re-export surface need to be
   a fixed `__all__` list, or do we use `from X import *`?**
   **My recommendation**: explicit `__all__` so a typo in
   a name is caught at import time, not at first call.
3. **Should `AkshareProvider` actually stay in
   `fund_data/providers/akshare.py` at 750 lines, or do
   we split its 6 capabilities into mixin classes?** The
   class is currently one big thing. **My recommendation**:
   no, the 0.3.0 RFC is "move the file, do not change it";
   splitting `AkshareProvider` is a 0.4.0 conversation.
4. **Test discovery.** `run_tests.sh` uses
   `unittest discover` rooted at `fund-data/scripts/tests/`.
   When we move tests next to the modules, the new files
   end up under `fund-data/scripts/fund_data/tests/`. The
   discover glob `test_*.py` is path-stable, but we
   should verify CI before PR 2 lands.

## Appendix C — the `fund_data.py` shim at the end of PR 6

```python
"""fund-data — legacy module shim.

The implementation has moved to the ``fund_data`` package
under this directory. This file exists so existing
``from scripts import fund_data`` imports keep working.
New code should use the package directly:

    from scripts import fund_data  # OK, the shim re-exports
    from scripts.fund_data import normalizers  # preferred for new code

.. deprecated::
    Imports from this file are stable through 0.3.x and
    will start emitting DeprecationWarning in 0.4.0. Move
    to ``from scripts.fund_data import <submodule>`` at
    your convenience.
"""
from __future__ import annotations

from .fund_data import *  # noqa: F401,F403  — see DeprecationWarning above
from .fund_data import __all__ as _legacy_all  # noqa: F401

import warnings as _warnings

_warnings.warn(
    "scripts.fund_data is a legacy module shim; the implementation "
    "lives in scripts/fund_data/ as a package. Importing from "
    "scripts.fund_data still works but will emit this warning "
    "in 0.4.0. See docs/superpowers/specs/2026-06-02-fund-data-0.3-split.md.",
    DeprecationWarning,
    stacklevel=2,
)
```

Approximately 25 lines. The `from .fund_data import *` works
because `fund_data.py` is a sibling of the `fund_data/`
package directory; the import resolves to the package, and
the package's `__all__` is honored.

(If that import resolution turns out to be ambiguous on any
supported Python version, the alternative is to spell out
the imports — but at 80 lines of `__all__` we'd rather
keep the `*` and risk the lint warning than copy-paste the
list into the shim.)
